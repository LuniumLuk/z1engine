# Proposal: opt-in unity builds for macOS

## Why

Measured on the reference machine (Intel i5-8257U 4C/8T, Apple clang 17), the `runtime` project dominates the macOS build (75 % of a clean build). A hand-built unity A/B (same flags, same 8-way parallelism, back-to-back, 0 errors / 0 warnings in both modes) shows:

| Mode | runtime project wall |
|------|----------------------|
| per-TU (current) | 147.1 s |
| unity, 8 blobs (58 TUs + 6 standalone vendor TUs) | **70.2 s (2.1x faster)** |

Unity translation units amortize header parsing and per-TU driver/`-MD` overhead across ~7 sources each, without touching the debug-info or optimization flags. Premake 5.0.0-beta8 cannot generate unity builds for the `gmake` action (`enableunitybuild` is implemented for VS2017+ only), so the blobs have to be generated by the project itself.

The experiment also surfaced two latent bugs worth fixing regardless: the GLFW define was spelled `glfw_INCLUDE_NONE` (the macro GLFW checks is `GLFW_INCLUDE_NONE`), so every TU including `glfw3.h` was silently pulling in Apple's legacy `<OpenGL/gl.h>`; fixing it alone made the per-TU runtime build ~12 % faster (167 s → 147 s). Five engine headers also lacked `#pragma once`, which unity builds cannot tolerate.

## What Changes

- **`generate --unity`** (macOS): premake writes deterministic unity blob translation units into `engine/intermediate/unity/<project>/` and builds those instead of the individual sources; sources that are unity-hostile by nature (`*_build.cpp` vendor implementation TUs, `pch.cpp`) stay standalone. The blobs are regenerated on every generate, so added/removed files are picked up by the existing `generate` step.
- **Unity is opt-in**: the default `generate` keeps today's per-TU build (the edit→build dev loop stays at ~19 s incremental instead of ~50 s for a full blob).
- **Source fixes required for unity** (also benefits the default build):
  - `GLFW_INCLUDE_NONE` spelling fix in `engine/runtime/premake5.lua` (stops pulling Apple's legacy GL header into every TU that includes `glfw3.h`).
  - `#pragma once` added to the five engine headers that lack it.
- **Docs/KB**: `openspec/kb/build.md` gains a unity-mode section with the measured numbers and the trade-offs; `openspec/kb/dev-scripts.md` documents `generate --unity`.
- **Windows is untouched** (the option is `system:macosx`-scoped; VS projects keep their normal file lists).

## Capabilities

### New Capabilities

- `unity-build`: opt-in macOS unity build mode — deterministic blob generation, exclusion rules for unity-hostile sources, correctness/warning guarantees, measured performance floor, documented incremental trade-off, and an unchanged default path.

### Modified Capabilities

- (none)

## Impact

- **Build system**: root `premake5.lua` (new option + blob-generation helper), `engine/runtime|editor|game|bakery/premake5.lua` (call the helper under the macOS+unity filter).
- **Sources**: `engine/runtime/premake5.lua` define fix; five headers gain `#pragma once` (`bakery.h`, `picking_system.h`, `renderer_2d.h`, `base.inl`, `string_utils.h`).
- **Dev CLI**: `dev/commands/generate.py` (passthrough + info line), `dev/z1.py` help text.
- **Generated artifacts**: `engine/intermediate/unity/**` (gitignored, regenerated, never committed).
- **No changes** to runtime behaviour, shaders, assets, Windows builds, or the default macOS build.
