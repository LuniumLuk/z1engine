# Contributing
> Summary: Development workflow, commit conventions, branching, AI attribution rules
> Scope: .github/, docs/CONTRIBUTING.md

## Branch Naming

| Type | Pattern | Example |
|------|---------|---------|
| Feature | `feature/<name>` | `feature/add-bloom` |
| Fix | `fix/<name>` | `fix/renderer-crash` |
| Chore | `chore/<name>` | `chore/update-dependencies` |

## Workflow

- Fork and clone the repository
- Create branch from `main`
- Implement changes following coding style
- Build and test via `python dev/z1.py dcv --auto`
- For performance-sensitive changes, ensure mapped benchmark suites pass (`python dev/z1.py benchmark --suite <name>` or `dcv --auto`)
- Commit with conventional format
- Open Pull Request against `main`

## Commits

- **Format**: Conventional Commits -- `<type>: <description>`
- **Types**: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`
- **AI prefix**: `[AI] feat: add bloom pass`
- **Trailers** (mandatory for AI commits):
  ```
  Generated-by: <agent-name>
  Co-authored-by: Copilot <223556219+Copilot@users.noreply.github.com>
  ```

## AI Attribution

- **File headers** (fully AI-generated files):
  - C++: `// [AI-GENERATED] This file was generated by an AI agent.`
  - Markdown: `<!-- [AI-GENERATED] -->`
- **Commit subject**: prefix with `[AI]` if primarily machine-generated
- **Minimal changes**: atomic commits, no unrelated refactoring

## Agent Operational Rules

- Work from repository root (`D:\z1engine\main`)
- Use `python dev/z1.py` commands (not raw batch scripts)
- Report intent before modifying files
- Do not add global linters or CI steps without approval
